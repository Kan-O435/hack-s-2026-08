# 妄想ポエム痛さ判定機(作品名未定)

> ハッカソン 2026-08 / テーマ:**妄想 × 技術の無駄遣い**
> 使用技術の軸:**音声認識**

---

## 1. これは何か

**ポエムを喋ると、その「痛さ」が数値化されて、冷笑される装置。**

真面目な技術(音声認識・形態素解析・埋め込み類似検索・LLM)を、
「今の発言、痛いですよ」と本人にわからせるためだけに全力で使う。

---

## 2. テーマとの接続

### 2.1 「妄想」の定義

「妄想」には3つの意味がある。

| | 意味 | 採用 |
|---|---|---|
| ① 精神医学用語 | 訂正不能な誤った確信(delusion) | × 病理の話になる |
| ② 日常語 | **根拠の乏しい情報から、頭の中で勝手に話を膨らませること** | **◎ これを採用** |
| ③ 仏教語(もうぞう) | 真実でないものを真実と思い込む迷いの心 | × 語源のみ |

②の本質は「**事実からの飛躍**」。
少ない入力から、勝手に壮大な話が組み上がる状態を指す。

### 2.2 妄想 × ポエム × 冷笑 の三層構造

同じ発言を、**視点の距離を変えて**見せるのがこの作品の背骨。

```
一人称(本人)  → 妄想    自分の中では主人公
二人称(語り)  → ポエム  誰かに聞かせるために抽象化する
三人称(観測)  → 冷笑    傍から見ると滑稽
```

笑いの発生源は **本人の真剣さと、傍から見た滑稽さのギャップ**。
冷笑はこのギャップを可視化する係。

### 2.3 なぜポエムが妄想に繋がるのか

ポエムの正体は「**現実を抽象化して語ること**」。

「昼飯どうしよう」を「俺たちはまだ途中なんだ」と言い換えると、
具体的な情報が消えて **解釈の余白** が生まれる。
妄想は、その余白に流れ込むもの。

> **ポエム = 解釈の余白を作る装置**
> **妄想 = 余白に勝手に注ぎ込まれる中身**

つまりポエムは妄想の**燃料**。こじつけではなく構造として繋がっている。

```
【現実】     そろそろ帰ろうかな        ← しょうもない
   ↓ 抽象化(本人が勝手にやる)
【ポエム】   俺たちは、まだ途中なんだ  ← 余白が生まれる
   ↓ 深読み(AIが勝手にやる)
【妄想】     彼にはかつて共に何かを
             目指した仲間がいた。
             おそらく3人。1人は既に…  ← 壮大
```

真ん中のポエムが**増幅器**になっている。この落差が笑いになる。

## 3. なぜ実装する必要があるのか(差別化)

### 3.1 前提となる批判

> 「ポエムを採点して講評する」だけなら、**Gemini や ChatGPT にプロンプトを投げれば終わるのでは?**

審査員も同じことを思う。**この問いに一文で答えられない作品は弱い。**

正直に言うと、現状の設計の中心部分(テキストを受け取って採点して講評を返す)は、
**実際プロンプトで足りる。** 差別化は別の場所から持ってくる必要がある。

### 3.2 チャットボットに原理的にできないこと

| # | できないこと | なぜ |
|---|---|---|
| ① | **発話中に介入する** | 貼り付けは「言い終わった後」にしか起きない |
| ② | **声の情報を読む** | テキストに落とした時点で、溜め・声量・話速・ピッチが消える |
| ③ | **過去のあなたと照合する** | 前回のあなたを知らない |
| ④ | **不意打ちする** | 自分で貼る = 覚悟している。覚悟したポエムは痛くない |

作品の独自性はこの4つに全部乗っている。逆に言うと、**この4つを削ると Gemini の劣化版になる。**

### 3.3 核心:②「声の情報」

**同じ言葉でも、言い方で痛さは何倍も変わる。**
そしてこれは、テキストに変換した時点で失われる情報。

例:「人生って、一度きりだよね」

| 言い方 | 痛さ |
|---|---|
| 早口で、ツッコミとして言う | 低い |
| **3秒黙ってから、声を落として、ゆっくり言う** | **高い** |

文字列は1文字も違わないのに、痛さがまったく違う。
**ここが「実装しないと存在しない」部分。**

### 3.4 発話痛さの特徴量

| 特徴量 | 取り方 | 痛さへの寄与 |
|---|---|---|
| **発話前の溜め** | VAD の無音長 | 3秒以上で大幅加点 |
| **声量の低下** | RMS の直前比 | 語り出しで落ちると加点 |
| **話速の低下** | モーラ数 / 秒 | 噛みしめるほど加点 |
| ピッチ下降 | F0 推定(YIN 等) | 低く落とすと加点 |
| 語尾の伸長 | 末尾母音の持続長 | 「〜なんだよねぇ…」 |
| 文中のポーズ | VAD | 「……」の実測値 |

実装コスト:**太字の3つ(溜め・声量・話速)は WebAudio API の RMS と無音長だけで取れる。**
これだけで成立するので、まずここまで。F0 は余裕があれば。

> ⚠️ Web Speech API はテキストしか返さない。
> 音声解析をやるなら**生の音声データを触れる経路が必要**(Discord VC / MediaRecorder)。
> concept.md §7 の入力方式の選定に直結する。

### 3.5 痛さの式を作り直す

```
痛さ = テキスト痛さ × 発話係数 × 累積補正
        ~~~~~~~~~~   ~~~~~~~~   ~~~~~~~~
        Gemini でも   ②が必要    ③が必要
        できる部分
```

**テキスト痛さは「材料」であって、作品の本体ではない。**

### 3.6 デモの決め手:同じ文を、違う言い方で

デモで**まったく同じ文を2回言う**。

| 言い方 | テキスト痛さ | 発話係数 | 総合 |
|---|---|---|---|
| 早口・平坦にツッコミとして | 62 | ×0.5 | **31** |
| 3秒溜めて、声を落として、ゆっくり | 62 | ×1.6 | **99** |

> 「テキストは1文字も違いません。**言い方だけが違います。**」

この一発で差別化が伝わる。**デモの最重要カットとして設計する。**

### 3.7 審査員への返し(用意しておく)

> 「これ、Gemini でもできますよね?」
>
> **「テキストを貼れば採点はできます。ただ、この作品が測っているのは "言い方" なので、貼った時点で情報の半分が消えます。」**

### 3.8 結論:優先度を組み替える

音声解析と発話ログの蓄積は「拡張」ではなく **MVP に入れる。**
テキスト採点の作り込み(軸を増やす、講評を凝る)は、そこまでやらなくても差がつかない。

詳細は §8 実装優先度。

## 4. 体験フロー

1. ユーザーがポエムを喋る
2. 喋っている**最中から**リアルタイムで加点が入る
3. 言い終わると痛さスコアが確定、称号が付く
4. 内訳(なぜ痛いのか)が分解表示される
5. 追い打ちの「わからせ」演出が入る
6. 記録が蓄積され、ランキング・黒歴史年鑑になる

## 5. コア機能:痛さスコアリング

### 4.1 評価軸(6軸・レーダーチャート表示)

| 軸 | 測るもの | 高得点例 |
|---|---|---|
| **主語のデカさ** | 語る対象の規模 | 「人生」「世界」「人間って」 |
| **勝手に代表する度** | 誰も頼んでない代弁 | 「俺たち」「僕ら」「みんな」 |
| **抽象度** | 具体的な情報の欠如 | 「何か」「いろいろ」「結局」 |
| **手垢度** | 語彙の既視感 | 「本当の自分」「answer」「絆」「輝き」 |
| **妄想度** | 現実からの距離 | 「いつか世界を変える」 |
| **反論不可能度** | 中身がなくて否定しようがない | 「人生は一度きりじゃん」 |

**「妄想度」を軸に必ず入れる。** これがテーマ回収の要。

> **痛さ = ポエム成分 × 妄想成分**

と定義できるので、3要素(妄想・ポエム・冷笑)が式の中で繋がる。

### 4.2 採点方式:LLMに丸投げしない(実装上の最重要点)

> 詳細な設計(ルーブリック・アンカー例・出力スキーマ・キャリブレーション手順)は [scoring.md](scoring.md) を参照。

**LLMだけで採点すると、同じ発言でも毎回違う点が出る。**
デモで2回言って点が変わると説得力が一瞬で死ぬ。骨格は決定論的に計算する。

```
痛さスコア = Σ(辞書ヒット × 重み) + 構文スコア   ← 決定論的、再現性あり
             × 時刻補正(深夜 ×1.5)
             × 場の補正(シラフ / 酒あり)
```

| 担当 | 手段 | 役割 |
|---|---|---|
| **辞書** | 手垢語リスト200語程度を手作り、各語に重み | 語彙ベースの加点 |
| **構文** | kuromoji.js で形態素解析 | 固有名詞率・数値の有無・一人称頻度・体言止め率 |
| **LLM** | Claude | **講評文と称号の生成のみ** |

こうすると、
- 数字が安定する(再現性がある)
- **「なぜその点なのか」を分解して見せられる** → わからせ効果が跳ね上がる

### 4.3 スコア計算の具体例

```
入力:「俺たちってさ、結局、熱量なんだよね」

  "俺たち"  +12  【勝手に代表する度】
  "結局"     +8  【抽象度】
  "熱量"    +15  【手垢度:起業家系】
  固有名詞 0 個   +20  【抽象度】
  数値 0 個       +10  【抽象度】
  ─────────────────────
  小計 65 × 深夜補正 1.5 = 97 点
```

## 6. わからせ演出(ここが作品の本体)

### ① リアルタイム加点(カラオケ採点機方式)

喋っている最中から、フレーズごとに加点がポップアップする。

```
「俺たちってさ…」      → "俺たち"  +12  【勝手に代表】
「結局、大事なのは」    → "結局"     +8  【抽象度】
「熱量なんだよね」      → "熱量"    +15  【手垢:起業家系】
```

**言い終わる前から刺さり始める**のが効く。逃げ場がない。

### ② スコア発表 + 称号

```
        痛 さ  8 7 点
        称号:深夜の哲学者
        全国 3,421人中 12位
```

### ③ 類似ポエム提示 ← 最強のわからせ

> この発言に酷似した投稿が、**847件** 見つかりました。
> 最古のもの:2013年3月14日 02:47

**「あなたの痛みは、オリジナルですらない」** と突きつける。
自分だけの言葉だと思っていたものが量産品だと知らせるのが、一番冷たい。

実装:事前に用意したポエムDBとの埋め込み類似度検索。
DBはLLMで痛いポエムを1000件ほど生成しておけば自前で作れる(実データ収集は権利面で面倒なので避ける)。

### ④ AI朗読(コスパ最強のトドメ)

高得点のポエムを、**荘厳なBGM付きで、他人の声で朗読して再生し直す。**
自分の言葉を他人の声で聞かされる羞恥は直撃する。実装はTTSだけなので安い。

### ⑤ 冷笑リアクション

点数に応じて実際に冷笑される。拍手ではなく、**静寂・咳払い・椅子のきしむ音**。

| スコア帯 | リアクション |
|---|---|
| 〜30 | 「はいはい」 |
| 31〜60 | 失笑、まばらな咳払い |
| 61〜85 | 完全な静寂、椅子がきしむ音 |
| 86〜 | 会場が凍る音 + 弾幕「出た」「明日後悔するやつ」 |

### ⑥ 冷笑エンジン4系統(飽き対策)

| 系統 | キャラ | 例 |
|---|---|---|
| **未来の自分** | 3年後のあなた | 「うわ、これ本気で言ってた」 |
| **匿名インターネット** | 弾幕 | 「出た」「深夜テンション」 |
| **評論家** | 冷静な批評 | 「1998年に誰かがやった」「B級」 |
| **統計** | データ | 「同種の発言、過去47件。実現率0%」 |

**一番強いのは統計による冷笑。** 悪口ではなく事実を突きつけるだけなのが最も冷たく、
かつ感情に頼らないので笑いが上品になる。

> あなたはこの3ヶ月で「本気出す」と **14回** 言いました。
> 平均間隔:6.4日。次回予測:8月31日。

蓄積ログをこんなことに使うのは**技術の無駄遣いとしても完璧**。

## 7. 入力方式

### 6.1 本命:Discord(ハイブリッド構成)

**Discord VC で入力 → Web画面で演出**、が最良。

```
Discord VC ──(ユーザーごとの音声ストリーム)──> Bot
                                                 │
                                          音声認識(Whisper)
                                                 │
                                             採点エンジン
                                                 │
                                    ┌────────────┴────────────┐
                              WebSocket                  Discord投稿
                                    │                          │
                            演出用Web画面              結果カード/ランキング
                          (デモで映すのはこっち)         (晒し = 冷笑と好相性)
```

**Discordを選ぶ最大の理由は「話者分離がタダで手に入る」こと。**

`@discordjs/voice` の receiver はユーザーごとに別々の音声ストリームをくれる。
Webで卓上マイク1本だと全員の声が混ざって誰の発言か分からないが、Discordなら最初から解決している。
**ランキング機能・個人ログ・黒歴史年鑑はすべて話者分離が前提**なので、ここが効く。

その他の利点:
- チーム全員が同じ場で使える(複数人の痛さ比較が自然に成立)
- 各自のヘッドセットなので会場ノイズに強い
- 結果をチャンネルに投稿すると「晒し」が成立し、冷笑と噛み合う
- デモで審査員にURLを配る手間がない

技術的注意:
- Discord の音声受信は discord.js がサポートしているが、Discord公式には非推奨扱い。動くが仕様変更リスクはある
- Opus ストリームを prism-media で PCM にデコードしてから Whisper に渡す
- 演出(縦書き字幕・レーダーチャート・弾幕)は Discord 上では表現しきれないので、**Web画面は必須**

### 6.2 代替:Web単体

Discord が間に合わない/詰まった場合のフォールバック。

```
マイク → Web Speech API (continuous: true, interimResults: true, lang: 'ja-JP')
       → 採点エンジン → 演出
```

- 実装コスト最小。マイク許可だけで動く
- 無音が続くと認識が止まるので `onend` での再起動処理が必須
- 話者分離ができないので、ランキング系機能は「手動で名前を選ぶ」等の妥協が必要
- デプロイして審査員に触ってもらう形も取れる

### 6.3 保険

**認識が死んだとき用に、テキスト入力欄を必ず裏に用意する。** ハッカソンの鉄則。

## 10. 注意点:冷笑の矛先(重要)

**冷笑は矛先を間違えると、笑いではなく不快になる。**
デモで審査員の発言を冷笑すると場が凍るリスクがある。冷笑系は見下される側に回った人間が一瞬で敵になる。

対策:

1. **矛先を「未来の自分」に固定する** — 自虐なので誰も傷つかない。最も安全かつエモい
2. **被験者は発表者自身にする** — 審査員は観客席から笑う側に置く
3. **最後に冷笑を裏切る** — 散々冷笑した後、最後の一行だけ「でも、まあ、悪くないんじゃない」と温度が戻す

3番目は特に効く。**冷笑しきらずに終わる**と作品の格が一段上がり、
「冷笑系の作品」から「冷笑を扱った作品」に変わる。審査ではここで差がつく。

議論の過程で出た他の候補。ピボット先の材料として残す。

| 案 | 内容 | 判断 |
|---|---|---|
| 独り言実況 | 日常の独り言をスポーツ実況/なろう系ナレーションに変換 | 妄想度◎だが今回は不採用 |
| 詠唱認識バトル | 中二病の詠唱を認識し、長さ・噛み・中二度でダメージ計算 | 妄想度◎。デモ映えも高い |
| モテ会話シミュレーター | 全肯定してくる架空の相手と会話 | 妄想度◎ |
| 脳内会議可視化 | 悩みに対し複数のAIペルソナが音声で議論 | 「葛藤」寄りで妄想から半歩ズレる |
| 言い訳ジェネレーター | 話し始めた言い訳を壮大に補完するカンペ | 妄想というより「嘘」 |
| 過剰考察マシン | ポエムを多ジャンルで同時に深読みして並列表示 | **痛さ判定に統合可能。要素として再利用できる** |
| 妄想検出器(現実照合型) | 発言を位置情報・時刻等の現実データと突き合わせ乖離度を測る | 「妄想度」軸の実装アイデアとして流用可 |

初期案の「ポエム検出器」単体は、**現実の言い換えであって事実からの飛躍がない**ため、
テーマ「妄想」への接続が弱いと判断。痛さ判定 + 冷笑の軸を足すことで解決した。
