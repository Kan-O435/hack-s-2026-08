### 論点

LLM の点がブレる原因は、モデルの能力ではなく **「痛い」の定義を渡していないこと**にある可能性が高い。
人間の採点者に基準を渡さず「採点して」と言うのと同じ状態。

この見立てが正しければ、必要なのは「学習」ではなく **「採点基準の言語化」**。
具体的には ルーブリック(§2)+ アンカー例(§3) を書く作業になる。

ただし、これは**まだ検証していない仮説**。§6 のキャリブレーションで実測して判断する。

> 副産物として、基準を言語化するとチーム内の「痛いとは何か」の認識が揃う。
> どの方式を採るにせよ、この認識合わせ自体は必要になる。

## 1. 役割分担

禁止したいのは**合計点の計算をLLMにやらせること**であって、分析そのものはLLMの主戦場。

```
LLM がやること
  ├── どこが痛いかの特定(文字範囲で指摘)
  ├── 軸ごとの評価(0-100)+ その根拠
  └── 講評文・称号の生成

コード側がやること
  ├── 軸スコアの重み付き合成 → 総合点
  ├── 時刻補正・場の補正
  └── ランキング・偏差値
```

**LLM は算数が不安定**なので、軸ごとの点だけ出させて合計は計算させない。
これだけで再現性がかなり上がる。

### 総合点の合成(コード側)

```
raw   = Σ(軸スコア × 重み)
total = clamp(raw × 時刻補正 × 場の補正, 0, 100)
```

| 軸 | 重み(暫定) |
|---|---|
| 手垢度 | 0.25 |
| 抽象度 | 0.20 |
| 勝手に代表する度 | 0.20 |
| 主語のデカさ | 0.15 |
| 反論不可能度 | 0.10 |
| 妄想度 | 0.10 |

| 補正 | 倍率 |
|---|---|
| 深夜(23:00-04:00) | ×1.5 |
| 酒あり | ×1.3 |
| シラフ・日中 | ×1.0 |

※重みはキャリブレーション(§6)で調整する。

## 2. ルーブリック(6軸)

軸ごとに **0 / 50 / 100 のアンカー**を言葉で定義する。これが採点の背骨。
**このセクションの質が、そのまま作品の質になる。**

### 手垢度 — その語彙をどれだけ多くの人が既に使っているか

| | 定義 | 例 |
|---|---|---|
| **0** | 固有名詞や数値を含み、その人にしか言えない具体性がある | 「昨日の鶏白湯、スープ2回おかわりした」 |
| **50** | ありふれた言い回しだが、まだ本人の実感が残っている | 「なんかやる気出ないんだよね」 |
| **100** | そのまま検索すれば同じ文が何千件も出てくる | 「本当の自分を探してる」「結局、熱量なんだよね」 |

### 勝手に代表する度 — 同意を取っていない他者をどれだけ巻き込んで語っているか

| | 定義 | 例 |
|---|---|---|
| **0** | 主語が自分ひとりに閉じている | 「俺は疲れた」 |
| **50** | 場にいる相手を含む | 「俺たち、そろそろ帰るか」 |
| **100** | その場にいない不特定多数を代弁している | 「僕らはみんな、何かを探してる」 |

### 妄想度 — 発言内容と現実との距離

| | 定義 | 例 |
|---|---|---|
| **0** | 検証可能で、現に起きている | 「今、雨が降ってる」 |
| **50** | 願望だが射程内にある | 「来年こそ痩せる」 |
| **100** | 検証不能なほど壮大 | 「いつか世界を変える」 |

### 主語のデカさ — 語る対象の規模

| | 定義 | 例 |
|---|---|---|
| **0** | 目の前の具体的な事象 | 「この味噌汁、しょっぱい」 |
| **50** | 自分の生活圏の抽象 | 「仕事ってさ、difficult だよね」 |
| **100** | 人類・世界・人生を主語に取る | 「人間ってさ、結局」 |

### 抽象度 — 具体的な情報の欠如

| | 定義 | 例 |
|---|---|---|
| **0** | 固有名詞・数値・日時を含む | 「8月27日、渋谷で3時間待った」 |
| **50** | 一般名詞のみだが指示対象は明確 | 「昨日の会議、長かった」 |
| **100** | 「何か」「いろいろ」「そういうの」で構成され、指示対象が不明 | 「なんかこう、いろいろあってさ」 |

### 反論不可能度 — 中身がなくて否定しようがない度合い

| | 定義 | 例 |
|---|---|---|
| **0** | 事実主張で、検証すれば白黒つく | 「昨日は雨だった」 |
| **50** | 意見だが根拠があり、議論の余地がある | 「この設計、N が増えると遅くなる」 |
| **100** | 同意する以外の反応が取りづらい | 「人生は一度きりじゃん」「大事なのは、結局、心だよ」 |

## 3. アンカー例(few-shot)= 実質の「学習データ」

ルーブリックだけだと点の絶対値がズレる。**採点済みの実例を10件ほどプロンプトに固定で埋め込む。**
これが一番効く安定化装置。

スコア帯を散らすのがコツ。

| 例文 | 総合 | 役割 |
|---|---|---|
| 「昨日の鶏白湯、スープ2回おかわりした」 | 3 | **下限アンカー** |
| 「今日、電車で足踏まれた」 | 8 | 低域 |
| 「なんか最近、疲れてるかも」 | 22 | 低域 |
| 「仕事って、何のためにやってるんだろうな」 | 41 | 中域 |
| 「まあ、人生いろいろあるよね」 | 48 | 中域 |
| 「大人になるって、こういうことなのかな」 | 63 | 中高域 |
| 「俺たちってさ、結局、熱量なんだよね」 | 87 | 高域 |
| 「僕らはみんな、まだ見ぬ本当の自分を探す旅の途中なんだ」 | 98 | **上限アンカー** |

> **上限と下限を必ず含めること。**
> 含めないとモデルが中央に寄って、全部60点台になる(LLM採点でよくある事故)。

## 4. 出力スキーマ

structured output / tool use で形式を固定する。

```json
{
  "spans": [
    { "text": "俺たち", "start": 0, "end": 3,
      "axis": "勝手に代表する度", "delta": 12,
      "reason": "話者以外の同意を取らずに複数人を代弁している" },
    { "text": "結局", "start": 5, "end": 7,
      "axis": "抽象度", "delta": 8,
      "reason": "議論を経ずに結論めいた語で締めようとしている" }
  ],
  "axes": {
    "主語のデカさ":     { "reason": "...", "evidence": "熱量",   "score": 75 },
    "勝手に代表する度": { "reason": "...", "evidence": "俺たち", "score": 90 },
    "抽象度":           { "reason": "...", "evidence": "結局",   "score": 85 },
    "手垢度":           { "reason": "2010年代のスタートアップ語彙", "evidence": "熱量", "score": 95 },
    "妄想度":           { "reason": "...", "evidence": "...",   "score": 40 },
    "反論不可能度":     { "reason": "...", "evidence": "...",   "score": 80 }
  },
  "title": "深夜の哲学者",
  "critique": "「熱量」という語の選択に、2014年頃のスタートアップ界隈の残響がある。...",
  "final_blow": "なお、この発言に具体的な行動計画は含まれていません。"
}
```

`spans` が **「今のポエムのここが痛い」** に直接対応する。
文字範囲を返させれば、UI 側でその部分をハイライトして加点を飛ばせる。

**スキーマ内のキー順は `reason` → `evidence` → `score` にする。**
根拠を書かせてから点を出させると、点が安定する(§5-②)。

## 5. 安定化テクニック

| # | 手法 | 理由 |
|---|---|---|
| ① | **temperature = 0** | 基本 |
| ② | **evidence-first** | 根拠を書かせてから採点させる。スキーマのキー順で強制できる |
| ③ | **合計はコード側で計算** | LLM は算数が不安定 |
| ④ | **軸ごとに独立採点** | 「総合的に何点?」と聞かない |
| ⑤ | **self-consistency** | 3回投げて中央値。精度が要るなら。レイテンシと引き換え |
| ⑥ | **長さバイアスを明示的に潰す** | LLM は長い文に高得点をつける癖がある。「文の長さは痛さと無関係。短くても痛いものは痛い」とプロンプトに明記 |

## 6. キャリブレーション手順

作ったら必ずやる。

1. テスト用ポエムを **30件** 用意する
2. **チーム全員が手で採点**して平均を取る(これが正解データ)
3. 同じ30件を LLM に投げる
4. 人間平均との**相関**と、同一入力を10回投げたときの**分散**を見る
5. **分散 ±5点以内 / 相関 0.8 以上** なら実用レベル
6. ズレている軸のルーブリック文言と重みを直す → 3 に戻る

2〜3周すれば、デモで「同じこと言ったら点が変わった」という事故は起きない。

## 7. 演出との噛み合わせ(二段構え)

**辞書と LLM の速度差が、そのまま演出になる。**

```
喋っている最中   → 辞書 + kuromoji.js が即座に加点ポップアップ(レイテンシ ≒ 0)
                   「"俺たち" +12」「"結局" +8」

言い終わった後   → LLM が数秒かけて深く分析
                   ドラムロール演出でレイテンシを隠す
                   → 軸別レーダー + 講評 + 称号
```

「機械的な即時反応」と「AIによる深い断罪」の二段になるので、
**待ち時間が演出として正当化される。** レイテンシ問題が消える上に、体験としても盛り上がる。

| 経路 | 担当 | 速度 | 使いどころ |
|---|---|---|---|
| 高速経路 | 辞書 + 形態素解析 | 即時 | リアルタイム加点 |
| 低速経路 | LLM | 数秒 | 最終スコア・講評・称号 |
