# 画面設計

> 親ドキュメント: [concept.md](concept.md)
> 関連: [db_design.md](db_design.md) / [api_design.md](api_design.md)

入力方式は「1人1台(各参加者が自分のスマホ/PCでアプリを開く)」を採用したことに伴う画面設計。
concept.md §7 で検討していた Discord VC / Web単体マイク1本 のどちらでもなく、
**Web複数クライアントが1つの「会話ルーム」に入る**方式で話者分離をタダで得る(詳細は本ドキュメント末尾の補足)。

---

## 1. 画面遷移図

```
┌──────────┐
│ S1 ログイン │  (トークンが端末にあればスキップ)
└─────┬────┘
      ▼
┌──────────────────────────────┐
│ S2 ホーム                      │
│  ・チャットに参加する            │
│  ・チャットを作る                │
│  ・履歴一覧(自分の過去ルーム)     │
└───┬───────────────┬──────────┘
    │参加             │作成           │履歴タップ
    ▼                ▼               ▼
┌─────────┐    ┌─────────┐      ┌───────────┐
│S4 参加    │    │S3 作成    │      │S7 結果      │
│ (パスコード)│    │ (ルーム名) │      │ (閲覧のみ)  │
└─────┬────┘    └─────┬────┘      └───────────┘
      │               │
      └───────┬───────┘
               ▼
        ┌─────────────┐
        │ S5 ロビー      │  参加者一覧をリアルタイム表示
        │ (パスコード表示)│  ホストのみ「開始」できる
        └──────┬──────┘
               ▼ 開始(host操作、全員に配信)
        ┌─────────────┐
        │ S6 会話中      │  マイクON、ライブ文字起こし
        │ (文字起こし)   │  各自の端末でリアルタイム加点ポップアップ(自分の画面のみ)
        └──────┬──────┘
               ▼ 終了(host操作、全員に配信)
        ┌─────────────┐
        │ S7 結果        │  痛さスコア・称号・講評・ルーム全体のまとめ
        │ (まとめ)       │  LLM処理待ちの間はローディング演出
        └─────────────┘
```

参加者全員が同時に S5→S6→S7 を遷移する(ホストの操作を Action Cable で全員に broadcast)。

## 2. 各画面の詳細

### S1. ログイン画面 `/login`

| 項目 | 内容 |
|---|---|
| 目的 | ニックネームだけでユーザーを識別する(パスワードなし) |
| 要素 | ニックネーム入力欄 / 「はじめる」ボタン |
| 送信後 | `POST /api/v1/sessions` でユーザー作成 + トークン発行 → 端末に保存(localStorage等)→ S2へ |
| 補足 | 端末に有効なトークンが既にあれば、この画面を経由せず自動的に S2 へ遷移する |

### S2. ホーム画面 `/home`

| 項目 | 内容 |
|---|---|
| 目的 | 参加/作成の入口、および自分の履歴の一覧 |
| 要素 | 「チャットに参加する」ボタン、「チャットを作る」ボタン、下部に履歴カード一覧(ルーム名・日時・自分のスコア/称号のサマリ) |
| データ取得 | `GET /api/v1/me/rooms` (finished のみ、新しい順) |
| 遷移 | 参加→S4 / 作成→S3 / 履歴カードタップ→S7(閲覧モード) |

### S3. チャット作成画面 `/rooms/new`

| 項目 | 内容 |
|---|---|
| 目的 | ルームを作り、パスコードを発行する |
| 要素 | ルーム名入力(任意、未入力ならデフォルト名) / 「作成」ボタン |
| 送信後 | `POST /api/v1/rooms` → 作成者は自動的に参加者(host)として登録 → S5へ |

### S4. チャット参加画面 `/rooms/join`

| 項目 | 内容 |
|---|---|
| 目的 | パスコードで既存ルームに入る |
| 要素 | パスコード入力欄 / 「参加」ボタン |
| 送信後 | `POST /api/v1/rooms/:passcode/join` → 成功したら S5へ |
| エラー | パスコード不一致・ルームが既に開始/終了済みの場合はその場でエラー表示(遷移しない) |

### S5. ロビー(参加者一覧)画面 `/rooms/:id/lobby`

| 項目 | 内容 |
|---|---|
| 目的 | ホストが人数を確認して会話を開始する起点。参加者は他に誰がいるか確認する |
| 要素 | パスコード表示(host共有用)、参加者リスト(入退室をリアルタイム反映)、hostのみ表示される「会話を始める」ボタン |
| リアルタイム | `RoomChannel` を購読し `participant_joined` / `participant_left` で一覧を更新 |
| 開始操作 | host が `PATCH /api/v1/rooms/:id/start` → `room_started` が全員に broadcast → 全員 S6 へ自動遷移 |

### S6. 会話画面(文字起こし) `/rooms/:id/live`

| 項目 | 内容 |
|---|---|
| 目的 | 会話中の発話をリアルタイムで文字起こし表示する |
| 要素 | 参加者ごとのライブ文字起こしログ(誰の発言か色分け)、経過時間、hostのみ「会話を終了する」ボタン |
| クライアント処理 | マイク入力→VADで発話区間検出→音声認識でテキスト化→**kuromoji.js + 辞書でリアルタイム加点ポップアップ(自分の端末内でのみ完結、他人には送らない)** |
| サーバー送信 | 発話区間が終わるたびに `POST /api/v1/rooms/:id/utterances` へ低頻度送信(テキスト+音声特徴量) → `utterance_created` が全員に broadcast されるので、他の参加者の画面にも文字起こしが流れる |
| 終了操作 | host が `PATCH /api/v1/rooms/:id/finish` → `room_finished` が全員に broadcast → 全員 S7 へ自動遷移(サーバー側では同時にLLM採点ジョブが走り出す) |

### S7. 結果画面(痛さ度・まとめ) `/rooms/:id/result`

| 項目 | 内容 |
|---|---|
| 目的 | 参加者ごとの最終スコア/称号/講評と、ルーム全体のまとめを見せる(演出の本体) |
| 要素 | 参加者ごとのスコアカード(スコア・称号・内訳レーダーチャート・講評文)、ルーム全体のまとめコメント、「ホームに戻る」ボタン |
| データ取得 | `GET /api/v1/rooms/:id/result`。LLM処理(低速経路)が終わっていない場合は `processing` を返すのでローディング演出を出し、`result_ready` を受けて再取得する |
| 履歴からの遷移 | 履歴カードから来た場合は同じ画面を「閲覧のみ」として表示(host/参加者の操作ボタンは出さない) |

## 3. リアルタイム同期の考え方

S5〜S7 は全参加者の画面が同期して遷移する必要があるため、Action Cable(Solid Cable)の `RoomChannel` を room 単位で購読する。詳細なイベント一覧は [api_design.md](api_design.md) §4 を参照。

**S6での加点ポップアップは自分の端末内だけで完結し、他の参加者の画面には表示しない**(concept.mdのリアルタイム処理はブラウザ内完結、という原則を維持)。他の参加者に流れるのはテキストの文字起こしのみ。

## 4. 補足:入力方式の決定について

concept.md §7 は「Discord VC(話者分離が無料)」 vs 「Web単体マイク1本(話者分離不可)」の二択で検討していたが、
**「1人1台、それぞれが自分の端末のマイクで自分の発話だけを拾う」**方式にすることで、
Discordに依存せずWebだけで話者分離を実質タダで得られると判断した。

- 各端末は近接マイクで自分の声だけを処理するので、ダイアライゼーション(話者分離のML)は不要
- 端末間で送るのはテキスト+音声特徴量の要約のみで、生の音声ストリームは送らない(軽い)
- concept.md §12 の未決事項「音声解析の経路(Discord VC / MediaRecorder)の選定」はこれで決定とする

concept.md 側の該当箇所は別途更新する。
